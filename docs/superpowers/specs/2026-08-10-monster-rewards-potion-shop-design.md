# 몬스터별 보상 및 물약 상점 설계

## 목표

픽셀 월드의 사냥 보상을 몬스터 난이도에 따라 차등화하고, 획득한 Gold를 중앙 마을의 연금술사 미아에게서 물약을 구매하는 데 사용하도록 한다. 구매한 물약은 단축키나 HUD 버튼으로 사용하며 수량은 브라우저에 저장한다.

이번 범위는 다음 플레이 순환을 완성한다.

1. 몬스터를 처치해 종류별 EXP와 Gold를 얻는다.
2. 중앙 마을의 미아에게 다가가 `F`를 눌러 상점을 연다.
3. Gold로 체력 또는 마력 물약을 구매한다.
4. `1`, `2` 단축키나 HUD 버튼으로 물약을 사용한다.
5. 구매와 사용 결과를 브라우저에 즉시 저장한다.

장비, 제작, 판매, 독과 이동속도 상태이상, 범용 슬롯 인벤토리는 이번 범위에서 제외한다.

## 몬스터별 사냥 보상

몬스터 종류를 키로 사용하는 고정 보상표를 `player-progression.js`에서 관리한다.

| 몬스터 | 내부 종류 | EXP | Gold |
|---|---|---:|---:|
| 불꽃 슬라임 | `fire-slime` | 3 | 1~3 |
| 숲 슬라임 | `forest-slime` | 4 | 2~4 |
| 물방울 슬라임 | `water-slime` | 5 | 2~5 |
| 멧돼지 | `boar` | 7 | 3~6 |
| 게 | `crab` | 8 | 4~7 |

Gold는 최솟값과 최댓값을 모두 포함하는 정수 난수로 계산한다. 전투 결과 알림은 실제 몬스터 이름과 획득량을 표시한다. 예: `멧돼지 처치! EXP +7 · Gold +5`.

퀘스트 진행과 사냥 보상은 분리한다.

- 퀘스트 수락 여부와 관계없이 등록된 모든 몬스터가 EXP와 Gold를 지급한다.
- `모험의 시작` 퀘스트를 수락한 상태에서는 세 종류의 슬라임만 처치 수에 반영한다.
- 멧돼지와 게는 사냥 보상만 지급하고 슬라임 퀘스트 진행도에는 영향을 주지 않는다.
- 한 공격으로 여러 몬스터가 죽으면 각 몬스터의 보상을 합산하되 HUD 갱신과 브라우저 저장은 공격 처리 마지막에 한 번 수행한다.
- 등록되지 않은 몬스터 종류는 보상을 지급하지 않고 게임을 계속 실행한다.

기존 퀘스트 완료 보상인 `15 EXP + 30 Gold`는 변경하지 않는다.

## NPC와 상점 진입

중앙 마을의 `상점 · 대장간` 건물 앞에 연금술사 미아를 추가한다.

미아의 NPC 데이터는 다음 정보를 가진다.

- ID: `mia`
- 이름: `연금술사 미아`
- 월드: `village`
- 역할: `shop`
- 상호작용 반경: 80
- 위치: 기존 상점 건물 앞의 통행 가능한 좌표

플레이어가 미아의 상호작용 반경 안으로 들어오면 `[F] 연금술사 미아의 상점 이용하기`를 표시한다. `F`를 누르면 상점 모달을 열고 게임 이동과 공격 입력을 막는다. 상점을 닫으면 Canvas에 포커스를 돌려주고 게임 입력을 복구한다.

아렌과 미아의 상호작용 반경이 겹치는 경우 기존 근접 NPC 탐색 규칙대로 플레이어와 더 가까운 NPC 하나를 선택한다. 아렌은 기존 퀘스트 대화를 열고, 미아는 상점을 연다.

## 상품과 인벤토리

첫 상점은 현재 전투 시스템에서 즉시 효과를 확인할 수 있는 소비 아이템 두 종류만 판매한다.

| 상품 | 내부 ID | 가격 | 효과 | 단축키 | 최대 보유 |
|---|---|---:|---:|---:|---:|
| 작은 체력 물약 | `hpPotion` | 10 Gold | HP 30 회복 | `1` | 99 |
| 작은 마력 물약 | `mpPotion` | 15 Gold | MP 25 회복 | `2` | 99 |

상품 정의, 가격, 회복량, 최대 보유량, 구매와 사용 결과는 신규 `shop-state.js`에서 관리한다. 이 모듈은 DOM이나 브라우저 저장소에 직접 접근하지 않는 순수 상태 로직으로 작성한다.

진행 데이터에는 인벤토리를 추가한다.

```js
{
  level,
  exp,
  nextLevelExp,
  gold,
  completedQuests,
  quests,
  inventory: {
    hpPotion: 0,
    mpPotion: 0,
  },
}
```

인벤토리는 이번 단계에서 두 물약의 중첩 수량만 보관한다. 아이템 배열, 빈 슬롯, 장비 상태는 만들지 않는다.

## 구매 규칙

구매 버튼 한 번당 선택한 물약 한 개를 구매한다.

1. 등록된 상품인지 확인한다.
2. 현재 수량이 99개 미만인지 확인한다.
3. 현재 Gold가 가격 이상인지 확인한다.
4. Gold를 차감하고 해당 물약 수량을 한 개 늘린다.
5. 상점, Gold HUD, 아이템 슬롯을 갱신한다.
6. 변경된 진행 데이터를 즉시 저장한다.

실패한 구매는 진행 데이터를 변경하거나 저장하지 않는다.

| 실패 원인 | 사용자 안내 |
|---|---|
| Gold 부족 | `Gold가 부족합니다.` |
| 최대 보유 | `물약을 더 이상 보유할 수 없습니다.` |
| 알 수 없는 상품 | 아무 값도 변경하지 않고 안전하게 종료 |
| 저장 실패 | `구매했지만 진행 상황을 저장할 수 없습니다.` |

화면의 구매 버튼은 Gold 부족이나 최대 보유 상태에서 비활성화한다. 실제 구매 함수에서도 같은 조건을 다시 검사해 중복 클릭이나 직접 호출로 Gold가 음수가 되는 것을 방지한다.

## 물약 사용 규칙

아이템 단축키와 HUD 버튼을 모두 지원한다.

- `1` 또는 첫 번째 아이템 슬롯 클릭: 작은 체력 물약 사용
- `2` 또는 두 번째 아이템 슬롯 클릭: 작은 마력 물약 사용
- `3`: 비어 있음

물약은 게임이 실행 중이고 플레이어가 생존해 있으며, 채팅 입력·NPC 대화·상점·종료 확인·포탈 전환이 활성화되지 않은 때만 사용할 수 있다.

체력 물약은 현재 HP가 최대 HP보다 낮고 수량이 한 개 이상일 때만 소비한다. 사용 후 HP는 `min(현재 HP + 30, 최대 HP)`로 계산한다. 마력 물약도 같은 방식으로 `25 MP`를 회복한다.

다음 상황에서는 물약을 소비하거나 저장하지 않는다.

- 물약 수량이 0개인 경우
- HP 또는 MP가 이미 최대인 경우
- 플레이어가 사망하거나 부활 대기 중인 경우
- 채팅, 대화, 상점, 종료 확인, 포탈 전환이 열린 경우

성공한 사용은 물약 수량, HP 또는 MP, HUD를 갱신하고 즉시 저장한다. 최대치를 초과하는 회복량은 이월하지 않는다.

## 상점 및 아이템 HUD

상점은 기존 모달 카드 시각 언어를 재사용하는 DOM 오버레이로 구현한다. 상점에는 다음 정보를 표시한다.

- `연금술사 미아의 상점` 제목
- 현재 보유 Gold
- 상품명, 회복 효과, 가격
- 현재 수량과 최대 보유량
- 상품별 구매 버튼
- 상점 닫기 버튼

구매 성공 시 Gold, 보유 수량, 버튼 활성 상태를 즉시 갱신한다.

기존 아이템 슬롯은 다음과 같이 변경한다.

- 슬롯 1: `작은 체력 물약`, `HP +30`, 현재 수량
- 슬롯 2: `작은 마력 물약`, `MP +25`, 현재 수량
- 슬롯 3: `비어 있음`

수량이 0이어도 물약의 이름과 효과는 유지하고 수량을 `×0`으로 표시한다. 키보드와 마우스 사용 경로가 같은 게임 메서드를 호출하게 하여 규칙이 달라지지 않도록 한다.

## 저장 형식 v3와 이전

저장 키를 `pixel-world.progress.v3:<정규화된 닉네임>`으로 올리고 페이로드 버전을 3으로 변경한다. v3 진행 데이터에는 `inventory`를 포함한다.

기존 v2 저장 데이터가 유효하면 다음과 같이 자동 이전한다.

- 레벨, EXP, 다음 레벨 필요 EXP 유지
- Gold 유지
- 완료 퀘스트와 현재 퀘스트 상태 유지
- `inventory.hpPotion = 0` 추가
- `inventory.mpPotion = 0` 추가
- 변환 결과를 v3 키에 저장

v1에서 v3로 직접 진입하는 이용자도 기존 v1 이전 규칙을 적용한 뒤 빈 인벤토리를 추가해 v3로 저장한다. v3 데이터가 있으면 이를 우선 사용한다.

검증 규칙은 다음과 같다.

- 물약 수량은 0~99 범위의 안전한 정수여야 한다.
- Gold는 0 이상의 안전한 정수여야 한다.
- 기존 레벨, EXP, 퀘스트 검증 규칙을 유지한다.
- v3 데이터가 손상되었어도 유효한 v2 또는 v1 데이터가 남아 있으면 해당 데이터를 이전한다.
- 사용 가능한 저장 데이터가 없으면 초기 진행 상태로 복구한다.
- 저장 접근이 실패해도 게임은 실행을 계속하고 사용자에게 저장 실패를 알린다.

## 모듈 책임

### `player-progression.js`

- 몬스터별 보상표 제공
- 몬스터 종류와 난수로 EXP·Gold 계산
- EXP, Gold, 레벨업, 초과 EXP 이월 처리
- 레벨에 따른 최대 HP·MP 계산 유지

### `shop-state.js`

- 상품 정의 제공
- 구매 가능 여부와 실패 원인 계산
- 구매 시 Gold 차감과 수량 증가
- 물약 사용 가능 여부와 실패 원인 계산
- 사용 시 수량 감소와 회복된 HP·MP 계산

### `progress-storage.js`

- v3 진행 데이터 검증과 직렬화
- v2 및 v1 데이터의 v3 이전
- 저장소 오류 시 안전한 초기 상태 제공

### `npc-data.js`와 `npcs.js`

- 미아 데이터 등록
- 미아의 구분 가능한 색상과 이름 렌더링
- 기존 최근접 NPC 탐색 규칙 유지

### `game.js`

- 몬스터 처치 시 종류별 보상 적용
- NPC 역할에 따른 대화 또는 상점 분기
- 구매, 물약 사용, HUD 갱신, 알림, 저장 연결
- 상점이 열린 동안 게임 입력 차단

### `main.js`, `index.html`, `styles.css`

- 상점 DOM 요소 연결
- 상점 열기·닫기 및 상품 버튼 제공
- 아이템 슬롯 내용과 수량 표시
- 기존 HUD와 플레이 영역을 가리지 않는 반응형 모달 스타일 제공

## 오류 처리와 일관성

- 구매와 물약 사용은 불변 상태 변환으로 구현하여 실패 시 원본 진행 데이터를 유지한다.
- Gold나 물약 수량이 음수가 되는 결과는 생성하지 않는다.
- 한 행동에서 상태 변경이 성공한 경우에만 HUD 갱신과 저장을 수행한다.
- 저장 실패는 구매나 사용의 메모리 상태를 되돌리지 않는다. 같은 세션에서는 결과를 유지하되 재접속 시 유실될 수 있음을 알린다.
- 상점을 닫는 동작 자체는 데이터 변경이 없으므로 저장하지 않는다.
- 기존 아렌 퀘스트, 채팅, 포탈, 사망·부활 입력 우선순위를 유지한다.

## 테스트와 완료 조건

### 단위 테스트

- 다섯 몬스터 각각의 EXP와 Gold 최솟값·최댓값
- 알 수 없는 몬스터 종류의 무보상 처리
- Gold가 충분할 때 구매 성공 및 정확한 차감
- Gold 부족, 99개 보유, 알 수 없는 상품의 무변경 처리
- HP·MP 정상 회복과 최대치 제한
- 수량 0 또는 최대 HP·MP 상태에서 무소비 처리
- v2와 v1 데이터의 v3 이전
- v3 인벤토리 검증과 재접속 복원

### 통합 및 UI 테스트

- 퀘스트 미수락 상태에서도 종류별 사냥 보상 지급
- 슬라임만 퀘스트 진행도에 반영
- 한 공격의 다중 처치에서 보상 합산 및 저장 한 번
- 미아 접근 안내와 `F` 상점 진입
- 구매 후 Gold, 상점 수량, 아이템 슬롯 동시 갱신
- `1`, `2` 키와 슬롯 클릭의 동일 동작
- 대화, 상점, 채팅, 사망, 포탈 전환 중 물약 사용 제한
- 기존 아렌 퀘스트와 저장 기능 회귀 없음

### 브라우저 플레이 점검

- 중앙 마을에서 미아를 찾고 상점을 열고 닫을 수 있다.
- 사냥으로 얻은 Gold가 몬스터 종류에 맞는 범위로 증가한다.
- 체력·마력 물약 구매와 사용 결과가 HUD에 즉시 반영된다.
- 같은 닉네임으로 재접속하면 레벨, EXP, Gold, 퀘스트, 물약 수량이 복원된다.
- 데스크톱 화면에서 상점이 플레이어 HUD, 퀘스트 추적기, 채팅과 겹쳐도 조작 가능한 우선순위를 가진다.
- 콘솔 오류가 없고 기존 캐릭터 및 몬스터 렌더링이 안정적이다.

모든 자동화 테스트와 브라우저 점검이 통과하면 구현을 완료한 것으로 본다.
