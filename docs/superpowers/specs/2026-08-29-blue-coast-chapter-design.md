# 푸른 해안 스토리 챕터 설계

## 목표

기존 2D Canvas 게임 엔진, 전투, 닉네임별 로컬 저장, NPC `F` 상호작용, 솔로·온라인 모드와 지역 협동 보스를 유지하면서 현재 단일 `coast` 월드를 네 개의 연결된 소형 맵으로 교체한다.

플레이어는 마리와 통신 장치를 복구하고, 과거 기록과 현재 구조 신호를 구분하며, 침수된 통신망에 남은 에코의 정체를 확인하고, 조수 코어 동굴에서 세라를 구출한다. 완료 시 해안 코어 조각과 활화산 접근권을 얻고 푸른 해변과 심층부 사이 지름길을 연다.

## 확정 범위

- 공통 지역·챕터 진행 구조를 먼저 만들고 푸른 해안을 첫 사용 사례로 연결한다.
- 태고의 숲 최초 보스 처치를 현재의 태고의 숲 완료 조건으로 사용한다.
- 솔로에서는 Firebase 없이 1인 기준 지역 보스를 실행한다.
- 솔로 보스의 HP, 공격, EXP와 Gold는 온라인 보스 정의의 1인 기준과 같다.
- 온라인 전투 중 연결이 끊기면 공유 보스 상태를 폐기하고, 솔로에서 같은 전투장에 다시 진입할 때 최대 체력 로컬 보스를 시작한다.
- 온라인에서는 기존 관리자 lease, 상태 2Hz 게시, 공격 요청 검증, 기여자별 보상, 3분 재등장을 유지한다.
- 일반 몬스터는 계속 각 브라우저에서 개인 사냥으로 실행한다.
- 구현과 검증은 별도 기능 브랜치에서 수행하며 배포와 `main` 병합은 하지 않는다.

## 범위 제외

- 활화산 내부 네 개 맵
- 최종 픽셀 코어 성역
- 실제 멀티 엔딩
- 로그인 시스템 교체
- 음성 파일 및 음성 합성
- 전투 시스템 전면 개편
- 게임 엔진 또는 프레임워크 교체
- 관련 없는 리팩터링
- QA 전용 진행 초기화·건너뛰기 UI

## 공통 지역과 물리 맵

`regionId`는 스토리와 개방 단위를, `mapId`는 실제 렌더링·위치 동기화 단위를 나타낸다.

| regionId | mapId | 이름 | 크기 |
|---|---|---|---:|
| village | village | 중앙 마을 | 2880×1800 |
| forest | forest | 태고의 숲 | 4320×3600 |
| coast | coast-beach | 푸른 해변 | 2160×1800 |
| coast | coast-wreck-bay | 난파선 만 | 2160×1800 |
| coast | coast-flooded-station | 침수된 통신소 | 2160×1800 |
| coast | coast-tide-core-cave | 조수 코어 동굴 | 2160×1800 |
| volcano | volcano | 끓어오르는 활화산 | 4320×3600 |

해안 네 맵의 합계 면적은 기존 해안 4320×3600과 같아 전체 월드 면적과 정적 레이어 메모리 예산을 유지한다.

`REGION_DEFINITIONS`는 입구 맵, 소속 맵, 선행 지역을 정의한다. `WORLD_DEFINITIONS`는 물리 월드 크기, 스폰, 포탈, 장애물, 일반 몬스터와 스토리 상호작용 위치만 정의한다. 포탈 잠금은 목적지 맵의 개방 여부로 판정하며, 게임 루프에 해안 전용 조건을 넣지 않는다.

## 진행 상태

진행 상태는 렌더링 객체나 좌표가 아닌 직렬화 가능한 값만 가진다.

```js
worldProgress: {
  unlockedRegionIds: ["village", "forest"],
  completedRegionIds: [],
  unlockedMapIds: ["village", "forest"],
  chapters: {
    coast: {
      repairedDeviceIds: [],
      collectedRecordIds: [],
      supportChoice: null,
      seraRescued: false,
      coopBossDefeated: false,
      coreFragmentObtained: false,
      shortcutUnlocked: false,
    },
  },
}
```

공통 진행 전이는 입력 객체를 변경하지 않고 새 상태와 발생 효과를 반환한다.

- `completeRegion(progress, "forest")`는 숲을 완료하고 푸른 해안·푸른 해변을 연다.
- `repairChapterDevice(progress, deviceId)`는 허용된 장치만 한 번 복구한다.
- `collectChapterRecord(progress, recordId)`는 허용된 기록만 한 번 수집한다.
- `chooseChapterSupport(progress, choice)`는 `sera`, `echo`, `mari` 중 하나를 한 번만 확정한다.
- `recordChapterBossDefeat(progress, "coast")`는 해안 보스 최초 처치를 기록한다.
- `rescueSera(progress)`는 해안 보스 처치 뒤에만 성공한다.
- `collectCoastCore(progress)`는 세라 구출 뒤 코어를 회수하고 해안을 완료한다.
- 해안 완료 효과는 활화산, 조수 코어 동굴 지름길과 완료 후 대사를 연다.

잘못된 순서, 미등록 ID와 반복 이벤트는 원본과 같은 의미의 복제 상태를 반환하고 보상이나 추가 효과를 만들지 않는다.

## 저장 호환

저장 형식을 `pixel-world.progress.v6:<nickname>`으로 올린다. v5 이하 키는 삭제하지 않고 이전 소스로만 읽는다.

- v1~v5의 레벨, EXP, Gold, 물약, 아렌 퀘스트, 직업별 장비와 보스 보상 영수증을 보존한다.
- v5에는 `worldProgress` 기본값을 추가한다.
- 하위 배열은 허용 목록으로 정규화하고 중복을 제거한다.
- 손상된 `worldProgress`만 기본값으로 복구하고 유효한 공통 진행과 장비를 버리지 않는다.
- 현재 위치는 저장하지 않는다. 재접속은 기존과 같이 중앙 마을에서 시작하고 개방 상태만 복원한다.

## 맵과 스토리

### 푸른 해변

- 마리를 처음 만난다.
- 해안 게와 물방울 슬라임이 지키는 조사 구역을 확보한다.
- `coast-beach-transceiver`를 복구한다.
- `sera-distress-current` 기록을 수집한다.
- 세라의 구조 요청을 들은 뒤 난파선 만을 연다.

### 난파선 만

- `wreck-relay-west`, `wreck-relay-deck`, `wreck-relay-east` 세 중계기를 복구한다.
- 세라·로안·가렌·선발대장의 서로 다른 시간대 기록을 수집한다.
- 현재 신호와 과거 기록 분류는 틀려도 기록을 잃지 않으며 다시 시도할 수 있다.
- 필수 기록과 중계기를 모두 확보하면 침수된 통신소를 연다.

### 침수된 통신소

- 주 통신 장치와 삭제 기록을 복구한다.
- 선발대장의 활화산 코어 운반 지시와 세라가 통신망을 차단한 이유를 확인한다.
- `sera`, `echo`, `mari` 중 하나를 지지한다.
- 모든 선택은 조수 코어 동굴을 열며 후속 대사만 바꾼다.

### 조수 코어 동굴

- 에코가 통신 기록과 코어 조각의 의식이 결합된 존재임을 밝힌다.
- 솔로에서는 로컬 보스, 온라인에서는 기존 협동 보스를 상대한다.
- 유효한 처치 뒤 세라를 구출하고 코어 조각을 회수한다.
- 활화산을 열고 푸른 해변과 동굴 사이 지름길을 활성화한다.

## 조사 구역과 상호작용

필수 목표는 미니맵과 목표 추적기에 180~260px 반경의 조사 구역으로 표시한다. 실제 장치의 정확한 위치는 상호작용 반경 안에서만 `F` 안내로 드러난다.

스토리 상호작용은 기존 NPC 상호작용과 같은 키와 입력 차단 규칙을 사용한다. 우선순위는 현재 활성 스토리 대상, 기존 NPC, 비활성 스토리 대상 순서다. 포탈은 기존처럼 자동 진입한다.

- 마리는 지정된 주요 지점에만 나타나며 전투·추적 AI가 없다.
- 세라는 최종 전투 뒤 상호작용 가능한 NPC로 나타난다.
- 에코는 NPC가 아니라 통신 장치의 파형과 작은 픽셀 얼굴로 렌더링한다.
- 대화는 짧은 페이지로 나누고 통신 기록은 별도 기록 목록에서 다시 볼 수 있다.

## 대화 선택

기존 단일 행동 대화 모델을 다중 행동 모델과 호환되게 확장한다. 기존 아렌 대화의 `action`과 `actionLabel`은 그대로 지원한다.

침수된 통신소의 세 선택은 한 번 확정하며 다음만 바꾼다.

- 세라·마리·에코의 후속 대사
- 마을 복귀 후 NPC 반응
- 최종장 직전 추가 대사
- 엔딩 후일담 일부 문장

선택은 보스, 세라 구출, 코어 회수, 활화산 개방을 차단하지 않는다.

## 보스 실행 경계

게임은 공통 보스 어댑터 계약을 사용한다.

```js
setMap(mapId, options)
update(dt, context, timestamp)
targetableBoss()
renderableBoss()
requestHit(payload)
consumeEvents()
clear()
```

- `CoopBossController`는 온라인 어댑터로 기존 Firebase 동작을 유지한다.
- `LocalBossController`는 같은 보스 정의와 적 AI를 사용하지만 네트워크를 호출하지 않는다.
- 로컬 보스는 `partySize = 1`의 `scaledBossMaxHp`를 사용한다.
- 로컬 encounter ID는 `local:<regionId>:<sequence>`, 온라인 ID는 기존 서버 ID를 사용한다.
- 로컬과 온라인 보상 영수증을 모두 `claimedBossRewardIds`에 기록해 동일 encounter 중복을 막는다.
- 챕터 완료는 encounter별 보상과 별도로 지역별 최초 한 번만 기록한다.
- 연결 해제 시 온라인 컨트롤러를 즉시 정리하고 snapshot을 로컬에 전달하지 않는다.
- 현재 전투장에 남아 있더라도 로컬 컨트롤러는 최대 체력의 새 encounter를 만든다.

숲 보스 최초 유효 처치는 `forest`를 완료해 해안을 연다. 해안 보스 최초 유효 처치는 해안 챕터의 `coopBossDefeated`를 설정한다. 보스가 쓰러진 것을 보기만 한 온라인 사용자는 챕터 처치와 보상을 얻지 못한다.

## 온라인 데이터

- 플레이어 위치와 머리 위 채팅은 물리 `mapId` 단위로 필터링한다.
- Firebase 플레이어·채팅 규칙은 새 네 해안 맵 ID와 2160×1800 경계를 허용한다.
- 해안 보스 채널은 조수 코어 동굴만 연결한다.
- 숲·활화산 보스 채널과 3분 재등장은 유지한다.
- 지역·스토리 선택·기록은 로컬 저장이며 Firebase에 게시하지 않는다.

## UI

- 기존 퀘스트 추적기 아래에 현재 챕터 목표 한 줄을 추가한다.
- 수집한 통신 기록을 다시 읽는 기록 버튼과 모달을 제공한다.
- 대화 선택은 세 개의 버튼과 닫기 버튼 사이에서 Tab·Shift+Tab 순환을 지원한다.
- 모바일에서는 선택 버튼과 기록 목록을 한 열로 표시하고 Canvas 조작 영역을 불필요하게 가리지 않는다.
- 솔로 로컬 보스 HUD는 온라인 참가자 수나 관리자 상태를 표시하지 않는다.

## 검증 기준

- 태고의 숲 보스 처치 전 해안 포탈은 잠겨 있다.
- 솔로·온라인의 숲 최초 처치가 해안을 연다.
- 해안 네 맵이 순서대로 열리고 개방한 맵은 재방문할 수 있다.
- 세 선택 모두 세라 구출과 활화산 개방으로 수렴한다.
- 저장 후 장치·기록·선택·구출·코어·지름길을 복원한다.
- 솔로 보스는 Firebase 요청 없이 1인 HP와 동일 보상을 사용한다.
- 온라인 보스의 기여자 보상·관리자 승계·3분 재등장을 유지한다.
- 연결 해제 뒤 공유 HP를 사용하지 않고 최대 체력 로컬 보스를 시작한다.
- 기존 v1~v5 저장이 오류 없이 이전된다.
- 세 직업, 일반 몬스터, 상점, 대장간, 인벤토리, 채팅과 모바일 조작 회귀가 없다.
- 전체 자동 검사와 브라우저 smoke에서 콘솔 오류가 없다.
