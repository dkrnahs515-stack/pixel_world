# 소설판 조사형 스토리 모드 제1장 설계

상태: 사용자 승인 완료  
작성일: 2026-09-11  
대상 저장소: `dkrnahs515-stack/pixel_world`  
대상 브랜치: `codex/story-mode-chapter-1`

## 목표

기존 픽셀 월드 RPG를 유지하면서, 소설판 제1장 「돌아오지 않은 이름들」을 처음부터 끝까지 플레이할 수 있는 1인 조사형 스토리 모드를 별도 페이지로 추가한다. 루트 첫 화면에서 기존 RPG와 조사형 스토리를 선택할 수 있어야 하며, 스토리 모드는 공식 삽화를 장면 전달의 중심 자산으로 사용한다.

## 범위

이번 구현은 제1장 완주형 검증판만 포함한다.

- 루트 첫 화면의 최상위 경험 선택기
- 기존 RPG 등록 화면으로 이동하는 경로
- 독립된 제1장 스토리 페이지
- 「처음부터」와 「이어하기」
- 제1장의 조사, 단서 비교, 근거 제출, 폐기 보류, 완료 화면
- 제1장 공식 삽화 2점의 실제 플레이 화면 배치
- 독립 로컬 저장과 자동 체크포인트
- 마우스, 터치, 키보드 접근
- 단위·정적 UI·브라우저 흐름 테스트

다음 항목은 이번 범위에 포함하지 않는다.

- 제2장 이후의 본문·진행·삽화
- 기존 RPG 사건과 소설판 사건의 결합
- 전투, HP, MP, Gold, 장비, 직업 또는 보상 코드
- Firebase Authentication, Realtime Database 또는 온라인 저장
- 삽화 재생성, 도트화, 크롭, 종횡비 변경 또는 내용 수정
- 운영 배포와 `main` 병합

## 원작 기준

사실과 대사는 `pixel-world-story-handoff-20260911.zip` 안의 확정 원고 `sources/novella/pixel-world-novella-manuscript.md` 제1장 3–234행을 기준으로 한다. 제1장의 결론은 선발대 전원의 생존 확정이 아니라, 생존 여부를 조사할 근거가 확보되어 명부 폐기를 보류하고 최소 인원의 숲 조사 임무가 편성되는 것이다.

기존 RPG의 아렌과 슬라임 사냥 퀘스트는 스토리 모드 제1장의 사건으로 사용하지 않는다.

## 진입 구조

루트 `index.html`은 기존 RPG 등록 폼보다 앞에 최상위 경험 선택기를 표시한다.

1. **기존 온라인 RPG**를 선택하면 현재 닉네임·직업·솔로/온라인·보상 코드 등록 화면을 표시한다.
2. **소설판 조사 스토리**를 선택하면 `story/` 전용 페이지로 이동한다.
3. RPG 등록 화면에는 최상위 선택기로 돌아가는 동작을 제공한다.
4. 스토리 페이지에는 루트 선택 화면으로 돌아가는 동작을 제공한다.
5. 기존 공식 플레이 URL은 유지하며 루트에서 두 경험을 모두 선택할 수 있어야 한다.

스토리 페이지는 RPG의 게임 루프, 클래스 선택, 진행 저장, 네트워크 및 Firebase 모듈을 import하지 않는다.

## 구성 요소와 책임

스토리 구현은 다음 책임 단위로 분리한다.

- `story/index.html`: 스토리 전용 시맨틱 마크업, 시작 화면, 조사 화면, 확인창, 완료 화면
- `story/story.css`: 삽화 중심 반응형 레이아웃, 문서 카드, 단서 목록, 선택 상태, 접근성 포커스
- `story/chapter-01-data.js`: 원문 기반 장면, 문서, 단서, 선택지, 통과 조건, 힌트, 삽화 메타데이터
- `story/story-state.js`: 상태 생성, 전이 검증, 단서 획득, 비교 완료, 근거 제출, 완료 판정
- `story/story-storage.js`: `pixel-world.story.v1` 저장의 직렬화, 검증, 복구, 삭제
- `story/story-controller.js`: DOM 이벤트, 화면 렌더링, 포커스 이동, 자동 저장, 시작·재개·초기화 제어
- `story/assets/chapter-01/`: 제1장 공식 PNG 2점만 포함

장면 데이터와 상태 전이는 DOM과 분리하여 브라우저 없이 단위 테스트할 수 있어야 한다.

## 플레이 화면

데스크톱은 큰 삽화 영역과 조사 패널을 나란히 배치한다. 좁은 화면에서는 삽화를 위에, 조사 패널을 아래에 배치한다. 삽화는 `object-fit: contain`으로 전체 구도와 원본 비율을 유지한다. 대사, 선택지, 진행 버튼은 이미지 위에 겹치지 않는다.

화면에는 다음 요소만 표시한다.

- 장 제목과 현재 조사 단계
- 큰 공식 삽화 또는 원문 기반 문서 카드
- 짧은 서술·대화
- 현재 행동 선택지
- 발견한 단서 목록
- 자동 저장 상태
- 첫 화면으로 돌아가기

RPG의 체력, 마력, 경험치, Gold, 퀘스트 추적기, 채팅, 미니맵, 전투 단축키, 직업 UI는 표시하지 않는다.

## 제1장 진행

### 1. 첫 임무

테오가 정식 모험가가 된 첫날 실종자 명부 폐기 업무를 받는다. 첫 번째 삽화 「고대 숲의 초보 궁수 테오」를 큰 세로 인물 영역에 표시한다. 그림의 숲은 인물 소개 배경이며 현재 장소인 길드 기록실로 설명하지 않는다.

### 2. 폐기 기준 확인

규정 카드에서 다음 세 조건을 모두 확인한다.

- 실종 뒤 5년
- 생존 신호 없음
- 회수 가능성 없음

세 조건을 확인해야 명부 조사로 진행한다.

### 3. 명부와 회수품 조사

루멘, 로안, 세라, 가렌의 이름과 부러진 선발대 공용 통신기, 로안의 빈 지도통을 조사한다. 실종자 명부를 사망자 명부로 표현하지 않는다.

### 4. 통신기 점검

플레이어가 폐기 전 최종 상태 확인 규정에 따라 전원을 점검한다. 다음 단서를 분리된 문서 카드로 제공한다.

- 첫 재생 12초, 두 번째 재생 11초
- 오늘 날짜 새벽 4시 52분의 새 수신 기록
- “우리가 남긴 길을 그대로 따라오지 마”라는 경고
- 짧게 한 번, 이어서 두 번 울리는 금속음

### 5. 나침반 소리 대조

출정 기록 0-1에서 로안의 주 나침반 덮개가 깨져 한 번, 두 번 부딪힌다는 문장을 선택한다. 현재 금속음과 대응하고, 주 나침반이 회수품 목록에 없다는 사실까지 비교해야 한다.

이 결과는 로안의 현재 생존을 확정하지 않는다. 로안과 관련된 현재 신호일 가능성이 있으므로 조사할 필요가 있다는 근거다.

### 6. 세 지역 기록 비교

태고의 숲, 푸른 해안, 활화산의 최종 보고서를 나란히 표시한다. 플레이어는 세 기록의 마지막 시각이 모두 “5년 전 셋째 달 17일, 4시 13분 22초”임을 발견한다.

제1장에서는 동일 시각의 원인을 설명하거나 뒤 장의 진실을 노출하지 않는다.

### 7. 폐기 보류 근거 제출

플레이어는 다음 핵심 근거를 조합한다.

- 새벽의 새 수신 기록
- 로안의 주 나침반 소리와의 대응
- 길드 현장기록 규정 제18조 4항

세 지역 동일 시각은 재조사가 필요하다는 보강 근거로 사용할 수 있다. “선발대 전원이 살아 있음이 확인됐다”는 주장은 통과시키지 않는다.

### 8. 폐기 보류와 숲 조사 임무

네 이름 아래에 “생존 여부 미확인. 폐기 보류.”를 표시한 후 두 번째 삽화 「지워질 네 이름, 돌아온 신호」를 큰 가로 장면으로 공개한다. 이 삽화는 통신기 발광과 세 지역을 암시하는 표시를 포함하므로 앞 단계에서는 공개하지 않는다.

통신기의 태고의 숲 방향 표시와 조사 임무 조건을 확인하면 제1장이 완료된다.

## 삽화 사용

사용 파일은 다음 두 점이다.

1. `01_제01장_고대 숲의 초보 궁수 테오.png` — 1024×1536
2. `02_제01장_지워질 네 이름, 돌아온 신호.png` — 1536×1024

원본은 그대로 보존한다. 화면 크기에 맞춘 브라우저 렌더링 외에 크롭, 재인코딩, 재그림, 인물·의상·소품 변경을 하지 않는다. 정확한 이름, 시각, 조항과 기록은 이미지의 작은 글씨나 OCR이 아니라 원문 기반 HTML 문서 카드로 표시한다.

초기 로딩에는 현재 장면의 삽화만 요청한다. 두 번째 삽화는 제1장 후반 공개 직전에 제한적으로 사전 로딩할 수 있다.

## 저장 구조

스토리 저장 키는 `pixel-world.story.v1`이다. 닉네임별 RPG 키 `pixel-world.progress.v7:<nickname>`과 연계하지 않는다.

저장 데이터는 다음 의미만 가진다.

- 스키마 버전
- 현재 체크포인트 장면 ID
- 발견한 단서 ID 목록
- 완료한 비교 ID 목록
- 제출한 근거 ID 목록
- 공개된 삽화 ID 목록
- 제1장 완료 여부

의미 있는 조사 단계가 완료될 때 자동 저장한다. 중간 선택 중인 미완성 UI 상태는 저장하지 않는다.

- **이어하기:** 마지막 완료 체크포인트에서 재개한다.
- **처음부터:** 확인창에서 승인한 경우에만 스토리 저장을 삭제하고 초기 상태를 만든다.
- **제1장 다시 보기:** 스토리 저장을 초기화한 뒤 제1장 첫 장면으로 이동한다.
- **첫 화면으로:** 저장을 유지하고 루트 선택 화면으로 이동한다.

## 오류 처리

- localStorage 읽기 실패 또는 손상된 JSON: 초기 상태로 복구하고 복구 안내를 표시한다.
- localStorage 쓰기 실패: 현재 세션의 플레이는 유지하고 진행을 저장할 수 없음을 알린다.
- 지원하지 않는 저장 버전: 기존 값을 덮어쓰지 않고 초기 상태로 시작하며 안내한다.
- 삽화 로딩 실패: 대체 설명과 재시도 버튼을 표시하되 필수 단서 접근을 막지 않는다.
- 잘못된 근거 제출: 벌점이나 단서 삭제 없이, 현재 자료가 증명하는 범위를 알려 주고 재시도하게 한다.
- 필수 단서가 없는 상태의 다음 단계 접근: 현재 장면을 유지하고 아직 확인할 자료를 구체적으로 안내한다.

## 접근성

- 조사 대상과 선택지는 실제 `button`, 문서 목록과 단서 목록은 시맨틱 HTML을 사용한다.
- 키보드만으로 모든 조사, 비교, 제출, 확인창 동작을 완료할 수 있어야 한다.
- 장면 전환 시 제목 또는 새 주요 패널로 포커스를 이동한다.
- 상태 변경과 저장 오류는 `aria-live`로 알린다.
- 선택 상태는 색상만으로 구별하지 않고 텍스트·테두리·아이콘을 함께 사용한다.
- 터치 대상은 모바일에서 충분한 크기와 간격을 갖는다.
- `prefers-reduced-motion`에서는 장면 전환 애니메이션을 제거한다.

## 테스트 전략

모든 새 동작은 실패하는 테스트를 먼저 작성하고 최소 구현으로 통과시킨다.

### 단위 테스트

- 초기 상태와 허용된 장면 전이
- 필수 단서가 없을 때 진행 차단
- 통신기 단서의 개별 획득
- 나침반 소리와 미회수품 비교
- 동일 시각 비교
- 올바른 근거 조합 통과
- 생존 확정 주장 거부와 재시도
- 제1장 완료 판정
- 저장·재개·초기화
- 손상 데이터와 저장 예외 복구
- RPG 저장 키를 읽거나 쓰지 않음

### 정적 UI 테스트

- 루트에 두 최상위 경험 선택지가 존재
- RPG 등록 폼이 삭제되거나 이름이 바뀌지 않음
- 스토리 페이지가 RPG·Firebase 모듈을 import하지 않음
- 두 삽화가 올바른 경로와 대체 텍스트로 연결됨
- 반응형·감소 모션·키보드 포커스 스타일 존재

### 브라우저 테스트

- 루트 → 기존 RPG → 기존 등록 화면
- 루트 → 조사형 스토리 → 처음부터
- 필수 단서 조사 → 비교 → 올바른 근거 제출 → 제1장 완료
- 새로고침 → 이어하기 → 마지막 체크포인트 재개
- 처음부터 선택 → 확인 → 스토리 진행만 초기화
- 스토리 플레이 중 Firebase 네트워크 요청 없음
- 모바일 크기에서 삽화와 조작 UI가 겹치지 않음
- 기존 RPG 브라우저 스모크 테스트 전체 통과

## 완료 기준

- 루트 첫 화면에서 기존 RPG와 소설판 조사 스토리를 선택할 수 있다.
- 기존 RPG의 현재 기능과 저장 데이터가 유지된다.
- 제1장을 다음 버튼 반복이 아닌 조사·비교·근거 제출로 완주한다.
- 공식 삽화 두 점이 승인된 시점에 크고 온전하게 표시된다.
- 그림에 없는 사물이나 읽히지 않는 문자를 증거로 요구하지 않는다.
- 제1장 결론이 “생존 여부 미확인, 폐기 보류”로 유지된다.
