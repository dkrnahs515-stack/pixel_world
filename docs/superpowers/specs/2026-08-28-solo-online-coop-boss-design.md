# 솔로·온라인 모드와 지역별 협동 보스 시스템 설계

## 목표

GitHub Pages를 Pixel World의 공식 게임 주소로 유지하면서 입장 화면에서 `솔로 플레이`와 `온라인 플레이`를 선택할 수 있게 한다. 솔로 플레이는 Firebase를 초기화하지 않고 기존 로컬 게임만 실행하며, 온라인 플레이는 최대 10명이 하나의 공개방에서 다른 플레이어·채팅·지역별 협동 보스를 공유한다.

일반 몬스터는 지금처럼 각 브라우저가 독립적으로 관리한다. 해안·활화산·태고의 숲에는 온라인 전용 협동 보스를 한 종류씩 추가하고, 같은 지역의 참가자들이 하나의 체력과 상태를 공유하며 함께 처치한다.

## 선행 조건

- `docs/superpowers/specs/2026-08-28-class-system-21-weapons-design.md`의 검사·궁수·마법사와 21종 무기 구현이 먼저 병합되어 있어야 한다.
- 기준 게임 엔트리는 `src/game-20260828-classes.js`와 `src/main-20260828-classes.js`이다.
- 직업별 근접·화살·마법탄·Q 스킬은 로컬 전투에서 이미 동작하고 있어야 한다.
- GitHub Pages를 공식 배포 주소로 사용하고 Firebase Hosting은 공식 플레이 경로에서 제외한다.

- 솔로 모드에서 채팅창·온라인 상태·접속자 수·다른 플레이어 완전 숨김
- 온라인 공개방 최대 10명 제한
- 온라인 연결 실패·장시간 연결 해제·방 정원 초과 시 솔로 자동 전환
- 플레이어 위치의 2Hz 적응형 전송과 화면 보간
- 현재 맵 플레이어만 받는 Firebase 쿼리
- 해안·활화산·태고의 숲의 협동 보스 3종
- 브라우저 한 대가 보스 AI·위치·체력·공격을 소유하는 권한 모델
- 관리자 이탈 시 남은 참가자에게 보스 권한 이전
- 검사·궁수·마법사의 협동 보스 공격 요청
- 공격 참여자 전원 동일 보상 1회 지급
- 보스 처치 후 3분 재등장
- 미수령 보상 24시간 보관과 만료 데이터 정리
- Firebase 보안 규칙, 정적·단위·브라우저·다중 세션 검증
- GitHub Pages 배포와 일반 주소 실플레이 검증

이번 작업에서 제외한다.

- 일반 몬스터의 위치·체력·사망 공유
- 플레이어 간 공격과 PvP
- 별도 권위 서버, Cloud Functions, 유료 Blaze 전환
- 파티·초대·비공개방·매칭 UI

- Firebase Hosting을 공식 게임 주소로 사용하는 구조
- 완전한 치트 방지와 서버 수준의 판정 정확도

## 확정된 사용자 흐름

1. GitHub Pages의 입장 화면에서 닉네임을 입력한다.
2. 검사·궁수·마법사 중 하나를 선택한다.
3. `솔로 플레이` 또는 `온라인 플레이`를 선택한다.
4. 솔로는 Firebase 모듈을 불러오지 않고 즉시 게임을 시작한다.
5. 온라인은 Firebase 익명 인증 후 공개방의 빈 슬롯을 확보한다.
6. 슬롯을 확보하면 다른 참가자·채팅·협동 보스가 활성화된다.
7. 공개방 10개 슬롯이 모두 찼거나 Firebase 연결에 실패하면 안내 후 솔로로 입장한다.
8. 게임 중 온라인 연결이 5초 넘게 끊기면 온라인 객체를 정리하고 같은 게임 세션을 솔로로 계속한다.
9. 솔로 전환 후 다른 참가자·협동 보스·채팅·온라인 접속자 표시를 즉시 제거한다.
10. 다시 온라인에 접속하려면 게임에서 나가 입장 화면에서 온라인 모드를 다시 선택한다.

## 입장 화면과 모드 상태

직업 선택 아래에 두 개의 모드 카드를 둔다.

- `솔로 플레이`: 혼자 스토리와 일반 사냥 진행, Firebase 미사용
- `온라인 플레이`: 최대 10명 공개방, 다른 모험가·채팅·협동 보스 활성화
- 첫 접속의 기본 모드는 `solo`로 둔다.
- 마지막 모드 선택은 직업 선호값처럼 브라우저 선호값으로 저장하되 입장할 때마다 변경할 수 있다.
- 닉네임·직업·모드가 모두 유효해야 입장 버튼이 활성화된다.
- 게임 중에는 모드 변경 버튼을 제공하지 않는다.

내부 모드 ID는 `solo`, `online` 두 값만 허용한다. Firebase 오류로 온라인 입장이 실패하면 세션 모드를 `solo`로 확정하고 온라인 연결을 재시도하지 않는다.

## 솔로 모드 계약

- Firebase SDK 동적 import를 호출하지 않는다.
- Firebase 익명 인증, Database 연결, 플레이어 쓰기, 채팅 읽기·쓰기를 수행하지 않는다.
- `chatPanel`, `networkBadge`, `onlinePresence`를 숨긴다.
- 원격 플레이어 컬렉션과 온라인 채팅 메시지를 비운다.
- 협동 보스를 생성하거나 Firebase 협동 보스 경로를 구독하지 않는다.
- 일반 몬스터·NPC·퀘스트·대장간·인벤토리·레벨·Gold·직업별 장비는 기존과 동일하게 동작한다.
- 진행 데이터는 같은 GitHub Pages origin의 브라우저 저장소를 사용하므로 솔로·온라인이 공유한다.

## 온라인 공개방과 정원

공개방 ID는 기존 `public`을 유지한다. 정원은 Firebase의 고정 슬롯 열 개로 관리한다.

```text
rooms/public/slots/0..9 = uid
```

- 온라인 입장 시 0번부터 9번 슬롯을 순서대로 트랜잭션으로 확보한다.
- 비어 있는 슬롯만 자기 UID로 바꿀 수 있다.
- 슬롯을 확보한 뒤에만 플레이어 정보와 채팅을 등록한다.
- `onDisconnect()`로 자기 슬롯과 플레이어 정보를 삭제한다.
- 열 슬롯이 모두 사용 중이면 Firebase 연결을 정리하고 솔로로 입장한다.
- 보안 규칙은 각 슬롯 값이 인증 UID 또는 `null`만 되도록 제한한다.

한 사용자가 개발자 도구로 여러 슬롯을 점유하는 완전한 악용 방지는 이번 범위가 아니다. App Check와 보안 규칙을 운영 방어선으로 사용한다.

## 플레이어 동기화와 무료 사용량

현재 20Hz 고정 전송을 다음 적응형 정책으로 바꾼다.

- 이동 중 위치: 초당 2회
- 이동 시작·정지·방향 변경·맵 변경·직업 변경·장비 변경: 즉시 전송
- 정지 상태: 30초마다 heartbeat만 전송
- 문서가 숨겨진 동안: 위치 전송 중지
- 원격 위치: 마지막 두 스냅샷 사이를 렌더 프레임에서 보간
- 원격 스냅샷이 1초 넘게 없으면 이동 표시를 중단

플레이어 목록은 전체 경로를 받은 뒤 클라이언트에서 맵을 거르지 않는다. `mapId` 인덱스와 `orderByChild("mapId").equalTo(activeMapId)` 쿼리로 현재 맵만 구독한다. 맵이 바뀌면 이전 listener를 해제하고 새 맵 listener를 연다.

## 협동 보스 정의

보스는 기존 몬스터 렌더러와 행동을 재사용하되 별도 `bossId`, 이름, 체력, 크기, 보상, 생성 위치를 가진다. 아래 값은 첫 QA를 위한 확정 초기값이며 플레이테스트 결과는 별도 밸런스 PR에서 조정한다.

| 지역 | bossId | 표시 이름 | 기존 외형·행동 | 생성 위치 | 기본 HP | EXP | Gold |
|---|---|---|---|---|---:|---:|---:|
| 해안 | `coast-core-shark` | 심해 코어 포식자 | `pirate-shark` | 2160, 2400 | 120 | 150 | 100 |
| 활화산 | `volcano-core-imp` | 화염 코어 군주 | `flame-imp` | 2160, 1500 | 160 | 220 | 150 |
| 태고의 숲 | `forest-core-troll` | 고대 코어 수호자 | `moss-troll` | 2160, 1400 | 200 | 300 | 200 |

보스의 최대 HP는 생성 순간 같은 지역의 온라인 참가자 수로 고정한다.

```text
maxHp = round(baseHp × (1 + 0.55 × (partySize - 1)))
partySize = 1..10
```

생성 이후 참가자가 들어오거나 나가도 해당 encounter의 최대 HP는 바뀌지 않는다. 다음 재등장 때 다시 계산한다.

## encounter 상태

각 지역은 동시에 하나의 encounter만 가진다.

```text
rooms/public/bosses/{mapId}
├─ state
│  ├─ encounterId
│  ├─ bossId, mapId, status
│  ├─ x, y, dir, moving
│  ├─ hp, maxHp, phase
│  ├─ targetUid
│  ├─ authorityUid, authorityEpoch, leaseUntil
│  ├─ partySize, spawnedAt, defeatedAt, respawnAt
│  └─ contributors/{uid}: firstHitAt, lastHitAt
├─ attacks/{uid}/{sequence}: attack request
├─ playerDamage/{uid}/{eventId}: boss-to-player damage
└─ rewardClaims/{encounterId}/{uid}: eligible, claimedAt, expiresAt
```

`status`는 `alive`, `defeated`, `respawning` 중 하나다. `encounterId`는 지역·서버시각·난수 키를 포함하며 재등장할 때마다 달라진다.

## 관리자 권한과 이전

- 해당 지역의 온라인 참가자 중 입장 시각이 가장 빠른 사용자가 권한 후보가 된다.
- 후보는 Firebase 트랜잭션으로 `authorityUid`, 증가한 `authorityEpoch`, 6초 뒤의 `leaseUntil`을 함께 기록한다.
- 관리자는 2초마다 lease를 연장한다.
- 다른 참가자는 lease가 서버 기준으로 만료된 뒤에만 권한 획득을 시도한다.
- 관리자는 보스 AI를 로컬 60Hz 시뮬레이션으로 실행하고 위치·행동 상태를 2Hz로 전송한다.
- 체력 변화, phase 변화, 타깃 변경, 사망은 전송 주기를 기다리지 않고 즉시 기록한다.
- 관리자가 나가면 보스는 최대 6초 정지할 수 있으며 다음 관리자가 마지막 확정 상태에서 이어받는다.
- 모든 상태 쓰기는 현재 `authorityUid`와 `authorityEpoch`가 일치할 때만 허용한다.

## 공격 요청과 피해 판정

일반 몬스터 공격은 기존 로컬 경로를 그대로 사용한다. 협동 보스에 대한 적중만 다음 요청으로 바꾼다.

```js
{
  attackId, sequence, uid, encounterId, bossId, mapId,
  classId, weaponId, attackKind,
  playerX, playerY, direction, createdAt
}
```

- 검사 근접 공격은 공격 범위가 보스와 겹칠 때 요청한다.
- 궁수·마법사의 투사체는 로컬 투사체가 보스와 충돌할 때 요청한다.
- 클라이언트는 적중 이펙트를 즉시 표시하되 체력 감소는 확정 상태를 따른다.
- 관리자는 UID·encounter·맵·직업과 무기 조합·공격 순번·공격별 재사용시간·대략적인 사거리를 검증하고, 피해량은 요청값을 신뢰하지 않고 `attackDefinition()`으로 다시 계산한다.
- 같은 UID의 같은 sequence는 한 번만 처리한다.
- 유효한 피해가 처음 적용되면 `contributors/{uid}`에 참가 기록을 만든다.
- 보스 체력은 트랜잭션 또는 authority epoch가 포함된 원자적 갱신으로 0 아래로 내려가지 않게 한다.
- 보안 규칙은 참가자가 자기 공격 경로에만 쓰도록 하고, 숫자·문자열·허용 범위·서버시각 편차를 제한한다.

브라우저 관리자 방식은 별도 권위 서버보다 조작 방지 수준이 낮다. 이번 프로젝트는 최대 10명의 소규모 체험형 협동을 목표로 하며 경쟁 순위·거래 가치가 있는 보상은 다루지 않는다.

## 보스 공격과 플레이어 피해

- 관리자는 현재 지역 참가자 위치 중 가장 가까운 생존자를 타깃으로 고른다.
- 기존 몬스터 행동이 유효한 공격을 만들면 대상 UID 전용 `playerDamage` 이벤트를 쓴다.
- 대상 브라우저는 현재 encounter·eventId·피해 상한을 확인하고 한 번만 HP에 적용한다.
- 공격 이벤트는 10초 후 읽기 대상에서 제외하고 다음 정리 때 삭제한다.
- 참가자 연결이 끊기면 타깃 후보에서 즉시 제외한다.

## 사망·보상·재등장

- 첫 번째 유효한 0 HP 갱신만 `defeated` 상태를 만든다.
- `contributors`에 기록된 모든 UID는 피해량과 관계없이 동일한 EXP·Gold 보상 대상이다.
- 마지막 타격 추가 보상과 피해량 순위는 없다.
- 각 UID는 `encounterId`별로 한 번만 보상을 받을 수 있다.
- 접속 중인 참여자는 처치 확정 후 브라우저 진행 데이터에 즉시 보상을 반영하고 원격 claim을 완료 처리한다.
- 처치 전에 연결이 끊긴 참여자는 `eligible` 미수령 보상을 유지한다.
- 미수령 보상은 다음 온라인 입장 때 지급하며 `expiresAt = defeatedAt + 24시간` 이후에는 지급하지 않는다.
- claim이 완료되기 전에 브라우저 저장이 실패하면 claim을 완료하지 않고 다음 입장에서 재시도한다.
- 보스는 `defeatedAt + 180초`에 새 encounter로 재등장한다.
- 같은 지역에 온라인 참가자가 없으면 재등장 상태를 만들지 않고 첫 참가자가 들어올 때 생성한다.

## 연결 해제와 솔로 전환

Firebase `/.info/connected`가 이전에 `true`였다가 5초 연속 `false`이면 온라인 연결 해제로 확정한다.

1. 플레이어·슬롯·채팅·보스 listener와 예약된 `onDisconnect`를 정리한다.
2. 세션 모드를 `solo`로 바꾼다.
3. 원격 플레이어, 온라인 채팅, 협동 보스와 관련 이펙트를 제거한다.
4. 채팅창, 네트워크 배지, 온라인 접속자 수를 숨긴다.
5. 플레이어의 현재 위치·HP·MP·진행·일반 몬스터는 유지한다.
6. `온라인 연결이 끊겨 솔로 모드로 전환되었습니다.`를 표시한다.
7. 같은 세션에서 자동 재연결하지 않는다.

초기 온라인 연결 실패와 방 정원 초과도 동일한 솔로 전환 결과를 사용하되 각각 원인을 안내한다.

## 데이터 보존과 정리

- 슬롯과 플레이어는 `onDisconnect()`로 즉시 삭제한다.
- 기존 채팅은 사용자당 최근 5개 정책과 연결 종료 삭제를 유지한다.
- 공격 요청과 플레이어 피해 이벤트는 처리 후 즉시 삭제한다.
- 진행 중 encounter 상태는 권한 이전을 위해 유지한다.
- 처치된 encounter·claim·stale authority 데이터는 최대 24시간 유지한다.
- 클라이언트는 온라인 입장·권한 획득 시 자기 지역의 24시간 초과 데이터만 제한적으로 정리한다.
- 데이터 정리는 게임 시작을 막지 않으며 실패 시 다음 권한자가 재시도한다.
- 이동 이력, 공격 전체 이력, 채팅 장기 이력은 저장하지 않는다.

## 보안 경계

- 모든 온라인 읽기·쓰기는 Firebase 익명 인증을 요구한다.
- 슬롯·플레이어·공격·claim은 자기 UID 경로만 직접 쓸 수 있다.
- 보스 상태는 현재 authority UID만 쓸 수 있다.
- 허용 맵·직업·무기·공격 종류·숫자 범위를 규칙으로 검증한다.
- App Check는 모니터링 후 Realtime Database에 enforcement를 활성화한다.
- 클라이언트 관리자 방식의 한계를 UI나 문서에서 경쟁형 멀티플레이로 표현하지 않는다.

## 모듈 경계

- `play-mode.js`: 모드 ID·선호값·입장 검증
- `network-publish-policy.js`: 2Hz 이동·즉시 변경·30초 heartbeat 결정
- `room-capacity.js`: 10개 슬롯 획득·해제 정책
- `coop-boss-data.js`: 보스 정의·HP 배율·보상·생성 위치
- `coop-boss-state.js`: encounter 정규화·권한 lease·공격 검증·보상 claim 순수 로직
- `coop-boss-network.js`: Firebase 경로·listener·트랜잭션·cleanup
- `coop-boss-controller.js`: 호스트 AI와 원격 보간을 조정하는 게임 계층
- `network.js`: 모드별 adapter 생성, 현재 맵 플레이어 구독, 연결 해제 전달
- `PixelRPG`: 세션 모드와 UI, 로컬 전투·협동 보스 연결, 진행 보상 반영

렌더러는 Firebase 객체를 직접 읽지 않고 controller가 제공한 정규화 보스 상태만 그린다. Firebase adapter는 DOM이나 Canvas에 접근하지 않는다.

## 검증 계약

### 단위 테스트

- 모드 선택과 기본 솔로
- 솔로에서 Firebase loader 미호출
- 2Hz 이동·정지·방향 전환·heartbeat 정책
- 열 개 슬롯 획득과 정원 초과
- 보스 정의·HP 배율·3분 재등장
- authority lease 획득·갱신·만료·epoch 충돌
- 동시 공격 순번 중복 방지와 체력 0 하한
- 세 직업·21종 무기 공격 검증
- 참가자 동일 보상과 encounter별 1회 claim
- 24시간 미수령 보상 만료
- 연결 해제 후 솔로 전환

### 보안 규칙 테스트

- 인증 없는 읽기·쓰기 거부
- 다른 UID 슬롯·공격·claim 쓰기 거부
- 11번째 슬롯 부재
- authority가 아닌 보스 상태 쓰기 거부
- 잘못된 맵·직업·무기·피해·시각 거부
- 유효한 상태·공격·claim 허용

### 브라우저와 실플레이

- 솔로에서 온라인 UI·Firebase 요청·원격 플레이어가 모두 없음
- 온라인 2명과 3명에서 같은 보스 위치·체력·사망 확인
- 검사·궁수·마법사가 같은 encounter에 피해 적용
- 두 명 동시 막타에서도 사망·보상 한 번
- 관리자 탭 종료 후 6초 이내 권한 이전과 동일 HP 유지
- 10명 입장 성공, 11번째 솔로 전환
- 온라인 연결 강제 차단 후 위치·HP·진행을 유지한 솔로 전환
- 보스 사망 후 180초 재등장
- 미수령 보상 재접속 1회 지급과 24시간 만료
- 콘솔 오류 0건, 전체 회귀 테스트 통과

### 사용량 검증

- 10명 이동 상태에서 플레이어 전송이 UID당 초당 2회를 넘지 않음
- 보스 상태 정기 전송이 지역당 초당 2회를 넘지 않음
- 정지 상태는 30초 heartbeat 외 전송 없음
- 현재 맵 외 플레이어·보스 listener가 없음
- 협동 보스가 없는 솔로 세션은 Firebase 요청 0건

## 배포 정책

- 공식 주소는 GitHub Pages 일반 주소다.
- QA는 `?qa=1`에서만 활성화하고 운영 주소에는 QA UI를 노출하지 않는다.
- Firebase Hosting 배포는 이번 기능의 완료 조건이 아니다.

- PR CI 성공 후 병합하고 GitHub Pages 배포 성공을 확인한 뒤 일반 주소에서 솔로·온라인 실플레이를 수행한다.
