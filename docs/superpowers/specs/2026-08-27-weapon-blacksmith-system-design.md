# 레벨 장비·대장간 시스템 설계

## 목표

플레이어가 레벨과 Gold를 활용해 여섯 단계의 상위 무기를 대장장이 브란에게 구매하고, 인벤토리에서 원하는 보유 무기를 직접 장착하며, 필요 없는 무기를 다시 판매할 수 있게 한다. 장착한 무기는 기본 공격 성능과 강공격 쿨다운을 바꾸고, 로컬 및 멀티플레이 캐릭터의 실제 검 외형에도 반영한다.

이번 범위는 다음 순환을 완성한다.

1. 사냥과 퀘스트로 레벨과 Gold를 올린다.
2. 중앙 마을의 브란에게 다가가 `F`로 대장간을 연다.
3. 요구 레벨과 가격을 확인하고 무기를 구매한다.
4. 인벤토리의 장비 영역에서 구매한 무기를 직접 장착한다.
5. 장착 무기의 기본 공격 피해·사거리와 강공격 쿨다운을 적용한다.
6. 필요 없는 무기를 구매가의 50%에 판매하거나 원래 가격으로 재구매한다.
7. 보유·장착 상태를 저장하고 다른 플레이어에게 장착 외형을 동기화한다.

방어구, 제작 재료, 무기 강화 확률, 내구도, 수리, 무기별 고유 스킬, 플레이어 간 거래는 이번 범위에서 제외한다.

## 확정 무기 카탈로그

무기는 이전 단계 구매 여부와 무관하게 요구 레벨만 충족하면 개별 구매할 수 있다. 피해와 사거리는 기본 공격에만 적용한다. 강공격은 기존 피해 `3`, 사거리 `96px`를 유지하며 장착 무기에 따라 쿨다운만 바뀐다. 기본 공격 쿨다운 `0.5초`, 기본 공격각 `120도`, 강공격의 나머지 전투 규칙은 변경하지 않는다.

| 무기 | 내부 ID | 요구 레벨 | 구매가 | 판매가 | 기본 피해 | 기본 사거리 | 강공격 쿨다운 |
|---|---|---:|---:|---:|---:|---:|---:|
| 시작 검 | `starter-sword` | 1 | 구매 불가 | 판매 불가 | 1.0 | 64px | 4.0초 |
| 카타나 | `katana` | 5 | 80G | 40G | 1.0 | 76px | 4.0초 |
| 강화 카타나 | `reinforced-katana` | 10 | 180G | 90G | 1.3 | 76px | 3.8초 |
| 상급 카타나 | `superior-katana` | 15 | 350G | 175G | 1.5 | 76px | 3.5초 |
| 정예 카타나 | `elite-katana` | 20 | 600G | 300G | 2.0 | 77px | 3.3초 |
| 명검 | `masterwork-katana` | 25 | 900G | 450G | 2.2 | 77px | 3.3초 |
| 강화 명검 | `reinforced-masterwork-katana` | 30 | 1,300G | 650G | 2.5 | 78px | 3.1초 |

판매가는 구매가의 정확히 50%인 고정 정수로 카탈로그에서 계산하거나 검증한다. 시작 검은 초기 장비이며 구매·판매 대상이 아니다.

## 모듈 구조

### `weapon-data.js`

- 변경 불가능한 무기 카탈로그를 제공한다.
- ID, 표시 이름, 요구 레벨, 구매가, 기본 피해, 기본 사거리, 강공격 쿨다운, 외형 키를 한곳에서 관리한다.
- 알 수 없는 ID 조회는 시작 검 정의로 안전하게 폴백할 수 있는 조회 함수를 제공한다.
- DOM, 게임 인스턴스, 저장소에 접근하지 않는다.

### `equipment-state.js`

- 초기 장비 상태를 생성한다.
- 구매, 판매, 장착 가능 여부와 실패 원인을 계산한다.
- 성공 시 복제된 다음 진행 상태를 반환하고 실패 시 원본을 변경하지 않는다.
- 레벨, Gold, 보유 목록, 현재 장착 ID의 관계를 검증한다.
- 화면 알림이나 브라우저 저장을 직접 수행하지 않는다.

### `combat.js`

- 기본 공격을 시작할 때 장착 무기의 피해와 사거리를 공격 정의에 결합한다.
- 강공격을 시작할 때 장착 무기의 강공격 쿨다운만 결합한다.
- 이미 시작된 공격은 도중에 장비가 바뀌더라도 생성 시점의 공격 값을 유지한다.
- 기존 경직, 히트 스톱, 공격각, 넉백, MP 소비 규칙을 유지한다.

### `progress-storage.js`

- 새 장비 상태를 포함하는 저장 형식을 검증하고 직렬화한다.
- 기존 v3, v2, v1 데이터를 새 형식으로 이전한다.
- 손상된 보유 목록과 장착 ID를 안전한 초기 장비 상태로 정규화한다.

### `npc-data.js`, `npcs.js`, `world.js`

- 중앙 마을에 브란과 대장간 시각 요소를 추가한다.
- 브란의 역할을 기존 미아의 `shop`과 구분되는 `blacksmith`로 정의한다.
- NPC와 시설 렌더링은 기존 Canvas 픽셀 스타일을 따른다.

### `game.js`, `main.js`, `index.html`, `styles.css`

- 브란 상호작용과 대장간 열기·닫기를 연결한다.
- 구매·판매·장착 결과를 Gold, 대장간, 인벤토리, 전투, 캐릭터 외형에 반영한다.
- 성공한 상태 변경마다 저장을 한 번 수행한다.
- 모달 포커스 순환, 키보드 입력 차단, 반응형 레이아웃을 기존 상점·인벤토리 패턴에 맞춘다.

### 네트워크 및 캐릭터 렌더링

- 플레이어 네트워크 상태에 `equippedWeaponId`만 추가한다.
- 원격 플레이어의 무기 ID는 외형 렌더링에만 사용한다.
- 원격 플레이어의 전투 수치는 현재와 마찬가지로 로컬 몬스터 전투 계산에 개입하지 않는다.
- 알 수 없거나 누락된 원격 무기 ID는 시작 검으로 표시한다.

## 진행 데이터와 저장 이전

진행 데이터에 독립된 장비 객체를 추가한다.

```js
{
  level,
  exp,
  nextLevelExp,
  gold,
  completedQuests,
  quests,
  inventory: {
    hpPotion,
    mpPotion,
  },
  equipment: {
    ownedWeaponIds: ["starter-sword"],
    equippedWeaponId: "starter-sword",
  },
}
```

저장 키와 페이로드 버전을 v4로 올린다. 같은 닉네임의 유효한 v3 데이터가 있으면 레벨, EXP, Gold, 퀘스트, 물약을 그대로 유지하고 초기 장비 객체만 추가해 v4로 저장한다. v2와 v1은 기존 이전 규칙으로 진행 상태를 복구한 뒤 같은 초기 장비 객체를 추가한다. 이전 저장 원본은 삭제하지 않는다.

장비 검증 규칙은 다음과 같다.

- `ownedWeaponIds`는 알려진 무기 ID만 포함하고 중복이 없어야 한다.
- 시작 검은 입력과 관계없이 항상 보유 목록의 첫 항목으로 복구한다.
- 상위 무기 보유에는 현재 레벨 제한을 다시 적용하지 않는다. 이후 레벨 데이터가 낮아져도 이미 산 무기를 잃지 않는다.
- `equippedWeaponId`는 반드시 보유 목록에 있어야 한다.
- 장착값이 누락되었거나 알 수 없거나 미보유 무기를 가리키면 시작 검으로 복구한다.
- 손상된 v4가 있으면 유효한 v3, v2, v1 순으로 복구를 시도한다.
- 사용 가능한 저장 데이터가 없으면 기존 초기 진행 상태와 초기 장비 상태를 사용한다.

구매·판매·장착 결과는 성공 직후 저장한다. 저장 실패는 세션의 메모리 상태를 되돌리지 않으며, 재접속하면 변경이 유실될 수 있다는 기존 저장 실패 안내를 표시한다.

## 브란과 대장간 월드 구성

브란은 중앙 마을의 기존 `상점 · 대장간` 건물 앞, 미아와 상호작용이 충돌하지 않는 통행 가능 위치 `x: 2460`, `y: 1000`에 둔다. 플레이어 충돌 반경 `32px`까지 장애물이 없음을 현재 월드 정의에서 확인했으며, 상호작용 반경은 `80px`로 한다.

브란의 확정 외형은 다음과 같다.

- 갈색 머리
- 파란 눈
- 가죽 앞치마
- 기존 NPC와 구분되는 대장장이 색상 조합
- 이름 표시: `대장장이 브란`
- 역할: `blacksmith`

대장간 시설에는 모루, 불붙은 화로, 무기 진열대를 배치한다. 화로는 짧은 불꽃 변화만 주고, 대형 오프스크린 버퍼나 매 프레임 새 객체를 만들지 않는다. 브란의 상호작용 반경 안에서는 `[F] 대장장이 브란의 대장간 이용하기`를 표시한다. `F`를 누르면 대장간을 열고 이동, 공격, 채팅, 물약 단축키를 차단한다.

미아는 기존 위치와 `shop` 역할을 유지하며 HP·MP 물약만 판매한다. 여러 NPC의 반경이 겹치면 기존 최근접 NPC 규칙으로 한 명만 선택한다.

## 대장간 구매 화면

대장간은 기존 모달 시각 언어를 재사용하되 미아 상점과 별도 DOM 오버레이로 구현한다. 제목, 현재 Gold, 시작 검을 포함한 현재 장착 무기, `구매`·`판매` 탭, 무기 목록, 닫기 버튼을 제공한다.

구매 카드에는 다음 내용을 표시한다.

- 무기 미리보기와 이름
- 요구 레벨
- 구매 가격
- 기본 공격 피해
- 기본 공격 사거리
- 강공격 쿨다운
- 현재 상태에 맞는 구매 버튼

버튼 상태는 다음과 같다.

| 상태 | 표시 및 동작 |
|---|---|
| 레벨 미달 | 카드를 어둡게 표시하고 `Lv.N 필요`, 버튼 비활성화 |
| Gold 부족 | `Gold 부족`, 버튼 비활성화 |
| 이미 보유 | `보유 중`, 버튼 비활성화 |
| 구매 가능 | `N G 구매`, 버튼 활성화 |

화면의 비활성화 상태와 별개로 실제 구매 함수가 모든 조건을 다시 검사한다. 구매 성공 시 Gold를 차감하고 보유 목록에 무기를 한 번 추가한다. 구매한 무기는 자동 장착하지 않는다. Gold HUD, 대장간 카드, 인벤토리 장비 목록을 즉시 갱신하고 저장을 한 번 수행한다.

실패한 구매는 상태를 변경하거나 저장하지 않는다.

| 실패 원인 | 사용자 안내 |
|---|---|
| 레벨 미달 | `요구 레벨에 도달하지 못했습니다.` |
| Gold 부족 | `Gold가 부족합니다.` |
| 이미 보유 | `이미 보유한 무기입니다.` |
| 시작 검 또는 알 수 없는 무기 | 아무 값을 변경하지 않고 안전하게 종료 |

## 대장간 판매 화면

판매 탭에는 시작 검을 제외한 보유 무기만 표시한다. 각 카드에는 현재 장착 여부와 고정 판매가를 표시한다.

판매 버튼을 누르면 무기명과 판매가가 포함된 확인창을 연다. 확인해야만 판매를 수행하고 취소하면 아무 상태도 바꾸지 않는다. 확인창도 키보드 포커스를 내부 버튼에 가두고 `Escape`로 취소할 수 있게 한다.

판매 성공 규칙은 다음과 같다.

1. 알려진 판매 가능 무기인지 확인한다.
2. 실제 보유 중인지 확인한다.
3. 구매가의 50%를 Gold에 더한다.
4. 해당 ID를 보유 목록에서 제거한다.
5. 어떤 상위 무기를 판매하든 항상 시작 검으로 교체한다. 판매하지 않은 다른 상위 무기를 자동 장착하거나 기존 장착을 유지하지 않는다.
6. Gold, 판매 목록, 인벤토리, 캐릭터 외형과 전투 수치를 갱신한다.
7. 변경된 진행 상태를 한 번 저장하고 장착 무기 ID를 네트워크에 반영한다.

판매한 무기는 요구 레벨을 충족하면 원래 구매가로 다시 살 수 있다. 판매 실패는 상태를 변경하거나 저장하지 않는다. 시작 검 판매, 미보유 무기 판매, 알 수 없는 ID는 차단한다.

## 인벤토리 장비와 장착

기존 인벤토리를 `물약`과 `장비` 영역으로 구분한다. 물약의 기존 단축키와 사용 규칙은 바꾸지 않는다.

장비 영역은 보유 무기를 카탈로그 순서로 표시한다. 각 장비 카드는 무기 이름과 주요 수치, `장착` 또는 `장착 중` 상태를 제공한다. 구매 직후에는 카드만 추가되고 현재 장비는 유지된다.

장착 성공 조건은 알려진 무기이고 실제 보유 중인 경우다. 성공하면 다음 작업을 같은 사용자 행동으로 처리한다.

- `equippedWeaponId` 변경
- 기본 공격 피해와 사거리 변경
- 강공격 쿨다운 변경
- 로컬 캐릭터 무기 외형 변경
- 장착 상태 UI 갱신
- 진행 데이터 저장 한 번
- 네트워크 장착 무기 ID 게시

미보유 또는 알 수 없는 무기의 장착 요청은 상태를 변경하거나 저장하지 않는다. 이미 장착 중인 무기를 다시 누르면 중복 저장이나 네트워크 게시를 하지 않는다.

## 무기 외형과 캐릭터 렌더링

무기는 외부 이미지 파일 대신 현재 게임과 같은 Canvas 픽셀 도형으로 그린다. 공통 손 위치와 방향 변환을 재사용하되 외형 키에 따라 검신 길이·폭·색상, 검등, 코등이, 손잡이, 장식을 바꾼다.

| 무기 | 확정 외형 |
|---|---|
| 시작 검 | 짧고 단순한 회색 검신, 갈색 손잡이 |
| 카타나 | 더 길고 얇은 은빛 날, 검은 손잡이 |
| 강화 카타나 | 밝아진 날, 단단한 검은 코등이 |
| 상급 카타나 | 두꺼운 검등, 더 날카로운 칼끝 |
| 정예 카타나 | 은빛 검신, 눈에 띄되 절제된 작은 금색 장식 |
| 명검 | 카타나보다 조금 길고 얇은 밝은 은색 날, 짙은 회색 또는 검은 검등, 검은 가죽·천을 촘촘히 감은 손잡이, 작은 금장이 있는 검은 코등이, 붉은색 또는 금색 문양, 손잡이 끝의 작은 금속 장식 |
| 강화 명검 | 명검의 실용적인 일본도 형태를 유지하면서 금장과 붉은 문양을 늘린 최고급 장인 제작품 |

명검 계열은 화려한 마법검이 아니라 실제 장인이 만든 고급 일본도 느낌을 유지한다. 과도한 오라나 지속 파티클은 추가하지 않는다.

대기, 이동, 기본 공격, 강공격 모두 현재 장착 외형을 사용한다. 공격 궤적의 시각 길이는 실제 유효 사거리와 일치시킨다. 원격 플레이어는 동기화된 `equippedWeaponId`로 같은 외형을 그리되 전투 판정은 만들지 않는다.

## 전투 수치와 소수 피해

공격을 생성할 때 현재 장착 무기 정의를 읽어 공격 스냅샷에 값을 넣는다.

- 기본 공격: 무기별 `damage`, `range` 적용
- 강공격: 기존 피해 `3`, 사거리 `96px` 유지, 무기별 `cooldown` 적용
- 기본 공격 쿨다운 `0.5초` 유지
- 강공격 MP 비용, 공격각, 준비 시간, 지속시간, 경직, 히트 스톱 유지

`1.3`, `1.5` 같은 소수 피해는 피해 적용 뒤 현재 HP를 소수점 한 자리로 정규화해 부동소수점 오차가 UI와 처치 판정에 누적되지 않게 한다. 피해 숫자는 `-1.3`처럼 표시한다. 현재 HP가 정수이면 `8/10`, 소수이면 `8.7/10`처럼 필요한 소수 한 자리만 표시한다. HP가 `0` 이하이면 기존과 동일하게 처치한다.

## 입력, 접근성, 반응형 규칙

- 대장간, 판매 확인창, 인벤토리 중 하나가 열리면 게임 이동·공격·채팅·단축 물약 입력을 차단한다.
- `Escape`는 가장 안쪽의 판매 확인창, 대장간 또는 인벤토리를 먼저 닫고 게임 종료 확인으로 전달되지 않는다.
- `Tab`과 `Shift+Tab`은 현재 열린 모달의 사용 가능한 요소 안에서만 순환한다.
- 비활성화된 구매·판매 버튼은 포커스 순환에서 제외한다.
- 탭 전환 후 첫 사용 가능한 버튼으로 포커스를 이동한다.
- 모달을 닫으면 게임 Canvas로 포커스를 돌린다.
- 좁은 화면에서는 무기 카드를 한 열로 접고, 목록만 내부 스크롤해 닫기 버튼과 현재 Gold가 화면 밖으로 밀리지 않게 한다.
- 대장간은 기존 HUD보다 위에, QA 패널과 판매 확인창보다 아래에 표시한다.

## 오류 처리와 일관성

- 구매, 판매, 장착은 순수 상태 변환으로 구현해 실패 시 원본 진행 데이터를 유지한다.
- 한 행동의 Gold와 장비 목록 변경은 부분 적용되지 않는다.
- Gold가 음수가 되거나 보유 목록에 중복 ID가 생기는 상태를 생성하지 않는다.
- 성공한 행동만 HUD를 갱신하고 저장한다.
- 저장 실패는 세션 상태를 유지하되 사용자에게 명확히 알린다.
- 네트워크 게시 실패는 로컬 장착과 저장을 취소하지 않는다. 연결이 복구되면 다음 정상 게시에서 최신 장착 ID를 보낸다.
- 대장간을 열거나 닫는 동작 자체는 진행 데이터를 저장하지 않는다.
- 브란과 미아의 역할을 분리해 물약 상점 동작과 장비 상점 동작이 서로의 상태를 변경하지 않게 한다.
- 기존 퀘스트, 채팅, 포탈, 사망·부활, QA 모달의 입력 우선순위를 유지한다.

## QA 지원

`?qa=1`에서만 노출되는 장비 점검 기능을 추가한다. 한 번의 QA 동작으로 현재 진행 상태를 Lv.30과 충분한 Gold로 설정할 수 있게 하여 여섯 무기의 잠금, 구매, 장착, 판매를 반복 점검한다. QA 조작도 기존 진행 저장 규칙을 따르며 QA 모드가 아닌 일반 URL에는 버튼과 동작을 노출하지 않는다.

QA 패널은 장비를 직접 지급하지 않는다. 실제 대장간 구매 경로를 통과시켜 Gold 차감, 보유 목록, 저장, UI를 함께 검증한다.

- 시작 검을 포함한 초기 장비 상태
- 이전 단계 미보유 상태에서 상위 무기 독립 구매

- 판매가 50% 지급, 보유 목록 제거, 재구매
- 시작 검과 미보유 무기 판매 차단
- 장착 여부와 관계없이 상위 무기 판매 시 항상 시작 검 장착
- 미보유 무기 장착 차단과 동일 장비 중복 처리
- v3, v2, v1의 v4 이전
- 중복·알 수 없는 보유 ID와 잘못된 장착 ID 복구

### 전투 및 렌더링 테스트

- 무기별 기본 공격 피해와 사거리
- 기본 공격 쿨다운과 강공격 피해·사거리의 기존 값 유지
- 무기별 강공격 쿨다운
- 소수 피해, HP 표시, 처치 경계
- 공격 생성 뒤 장비 변경 시 기존 공격 스냅샷 유지
- 방향과 공격 상태별 일곱 무기 외형 키 사용
- 공격 궤적과 실제 기본 공격 사거리 일치
- 유효·누락·알 수 없는 원격 무기 ID 렌더링

### 통합 및 UI 테스트

- 브란의 위치, 역할, 최근접 NPC 상호작용
- `F`로 브란 대장간을 열고 미아는 기존 물약 상점을 여는 역할 분리
- 구매·판매 탭과 무기별 수치 표시
- 레벨 미달, Gold 부족, 보유 중 버튼 상태
- 구매 후 자동 장착되지 않고 인벤토리 장비 카드만 추가
- 인벤토리 직접 장착 후 외형·전투 수치·저장 동시 반영
- 판매 확인·취소·확정과 모든 상위 무기 판매 후 시작 검 복귀
- 모달 입력 차단, `Escape`, 포커스 순환, 모바일 한 열 레이아웃
- 장착 ID의 네트워크 직렬화와 레거시 원격 상태 폴백
- 구매·판매·장착 성공당 저장 한 번, 실패 시 저장 없음

### 브라우저 플레이 점검

- 중앙 마을에서 브란과 모루·화로·무기 진열대를 식별할 수 있다.
- 브란과 미아가 각자의 상점을 정상적으로 연다.
- Lv.30 QA 상태에서 여섯 무기의 잠금 해제, 구매, 인벤토리 장착, 판매, 재구매를 확인한다.
- 무기별 길이·색상·장식이 대기와 두 공격에서 구분된다.
- 기본 공격 피해·사거리와 강공격 쿨다운이 표시 수치와 일치한다.
- 두 브라우저에서 한 플레이어의 장착 변경이 다른 플레이어 외형에 반영된다.
- 재접속 뒤 레벨, Gold, 물약, 퀘스트, 보유 무기, 장착 무기가 모두 복원된다.
- 데스크톱과 모바일 크기에서 대장간과 인벤토리를 조작할 수 있다.
- 전체 자동 테스트, JavaScript 문법 검사, GitHub Actions, GitHub Pages 배포가 성공하고 게임 코드 콘솔 오류가 없다.

## 완료 범위

이 설계의 완료는 여섯 상위 무기의 구매·판매·재구매, 인벤토리 직접 장착, 전투 수치 적용, 브란과 대장간 시설, 로컬·원격 캐릭터 외형, v4 저장 이전, QA와 자동·브라우저 검증이 함께 동작하는 상태를 뜻한다. 일부 기능만 먼저 배포하거나 외형·네트워크 동기화를 후속 작업으로 미루지 않는다.
